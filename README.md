# Instapro

MVP социальной сети для обмена фотографиями. Доработка чужого кода: связал вёрстку с API, сделал страницу добавления поста, страницу постов пользователя, лайки, удаление постов и немного улучшил интерфейс.

## Что было в стартовом репозитории

- Структура приложения и переключение между страницами.
- Авторизация и регистрация.
- Компонент загрузки изображений в облако.
- Компонент шапки сайта.
- Статичная вёрстка списка постов без связи с API.

## Что реализовано

Основные задачи:

- Интеграция вёрстки списка постов с API: рендер постов из массива posts, динамические данные (автор, изображение, описание, дата, лайки).
- Страница добавления поста: поле описания, загрузка изображения через готовый компонент, валидация (описание и фото обязательны), отправка в API, редирект в ленту.
- Страница постов конкретного пользователя: получение через GET /user-posts/:id, переход по клику на автора, отдельная шапка пользователя.
- Лайки: постановка и снятие через API, смена иконки like-active / like-not-active, счётчик лайков из длины массива likes, обновление без перезагрузки страницы. Работает и в общей ленте, и на странице пользователя.
- Заменил personalKey на свой (alex_den), чтобы получить независимый набор данных.

Дополнительно:

- Удаление поста через DELETE /:id. Кнопка "Удалить" показывается только автору поста (сравнение user.id с post.user.id), подтверждение через confirm, обновление списка после удаления.
- Защита от XSS: хелпер escapeHtml для экранирования пользовательских строк (description, name, imageUrl, id) во всех шаблонах. HTML-теги в формах отображаются как текст.
- Нормализация \_id в id при чтении пользователя из localStorage. Особенность бэкенда: авторизация возвращает \_id, а посты отдают id.
- Анимация "биение сердца" при клике на лайк, пока не пришёл ответ API. Снимается в finally, не залипает при ошибке.
- Стилизация кнопки удаления: красная рамка, hover и active состояния, cursor: pointer, выравнивание рядом со счётчиком лайков.
- Защита от повторных кликов по лайку, пока идёт запрос (флаг dataset.loading).
- Синхронизация локального массива posts после лайка и удаления, чтобы состояние не слетало при переходах между страницами.
- Обработка ошибок API: catch на добавлении поста, удалении, лайке и загрузке изображения, с сообщениями пользователю.
- Loading page перед загрузкой постов пользователя, как на странице общей ленты. Заодно убрал бесконечный цикл при ошибке getUserPosts.
- Исправил баг в upload-image-component.js: document.querySelector заменил на element.querySelector, чтобы компонент работал при нескольких загрузчиках на странице.
- Относительный формат даты ("19 минут назад") через date-fns с локалью ru.
- Шапка на странице добавления поста и на странице пользователя через общий renderHeaderComponent, без расхождений с другими страницами.

## Тестирование

Проверял по тест-плану из задания:

- Регистрация и авторизация: успешные и ошибочные сценарии, сохранение сессии после обновления, выход.
- Общая лента: доступна авторизованным и неавторизованным.
- Лента пользователя: переход по клику на автора, доступна всем, данные из user-posts.
- Лайки: работают у авторизованных, не работают у неавторизованных, счётчик обновляется без перезагрузки.
- Добавление поста: только для авторизованных, валидация описания и фото, пост появляется сразу.
- XSS: HTML-теги в описании и имени отображаются как текст.
- Удаление: кнопка видна только автору, пост исчезает после подтверждения.

## Запуск

Открыть index.html через локальный сервер (например, Live Server в VS Code), приложение использует ES-модули.

## Стек

Vanilla JS (ES-модули), HTML, CSS. date-fns через CDN для форматирования дат. API: https://webdev-hw-api.vercel.app (Instapro v1, загрузка файлов, пользователи).
